# 05 售后退款业务

## 售后流程:申请→审核→打款

用户在订单页发起售后 → `litemall_aftersale` 新增一行(status=1 用户已申请),订单 `order_status=202` → 商家审核:同意则打款,售后 status=3(退款成功),订单转 203,记 handle_time、订单 refund_amount/refund_type/refund_time;拒绝则 status=4。用户中途可撤消(status=5)。**退款资金流**以订单 refund_amount 为准,可部分退款(金额小于实付)。

## 售后的三种类型及业务差异

type=0 未收货退款(仅退款,货未发出或退回途中,73 条,多为发货前反悔);type=1 已收货退款(无需退货,钱货两清后只退钱,4,267 条,绝对主流——家居大件退货物流成本高,商家倾向只退款不退货);type=2 退货退款(用户寄回商品,当前 0 条)。查"退货率"与"退款率"不同:本库无真实退货,只有退款。

## 退款原因分布与业务解读

reason 字段取值:七天无理由退换货、不想要了、商品与描述不符、质量问题、发货太慢、尺码不合适。分析口径:`SELECT reason, COUNT(*) FROM litemall_aftersale WHERE deleted=0 GROUP BY reason ORDER BY 2 DESC`。"商品与描述不符""质量问题"占比升高提示货品管控问题;"七天无理由/不想要了"属正常购物后悔,运营关注意义有限。

## 退款率的健康度判断

本库整体退款率约 8.6%(单量口径)。行业参照:自营家居电商退款率 5%-15% 属正常区间;若某单品/某类目退款率显著高于整体,做下钻:按 goods_id 关联 order_goods 找高退款商品,或按 reason 细分。

## 退款时效

商家处理时长 = 售后 handle_time − add_time(仅 status=3 已完成的记录)。行业期望:48 小时内处理完毕。用户侧"申请到到账"还要加平台支付通道时间,库中无此数据。

## 售后与订单状态的对应关系(查数据别查错表)

"退款中有多少单"查订单表 status=202;"已完成退款多少单"= status=203;"退款原因分布/处理时长"查售后表;"退了多少钱"查订单表 SUM(refund_amount)(203 或全部,按用户口径确认)。售后表与订单表通过 order_id 一对一(同一订单同时段一个售后单)。
