# 01 业务概念与口语映射

用户口语 → 业务概念 → 查询对象的映射表。每个条目自包含,命中任一同义说法即可定位表和字段。

## 用户问"用户/客户/顾客/买家/会员" → litemall_user

"用户""客户""顾客""买家"同义,对应 `litemall_user` 表。"会员"按语境:泛指注册用户用 user 表;特指等级时用 `user_level`(0 普通,1 VIP,2 高级VIP)。"下单用户/购买用户"= `litemall_order` 中出现过的去重 `user_id`(当前 600 人);"注册用户"= user 表 `deleted=0`。用户身份敏感字段(mobile、password、weixin_openid)不要在结果中展示。

## 用户问"赚了多少钱/利润/盈利/毛利" → 无成本字段,用销售额回答并声明

库中没有成本、费用字段,无法计算真实利润(盈利 = 销售额 − 进货成本 − 费用)。应回答**销售额**并声明局限:"库中无成本数据,无法计算利润;统计期内销售额(实付)为 SELECT SUM(actual_price) FROM litemall_order WHERE order_status IN (201,301,401,402,403) AND deleted=0"。若用户要"净回款",用销售额减 SUM(refund_amount)。

## 用户问"卖了多少钱/营业额/流水/营收/成交额/销售额/GMV" → litemall_order.actual_price

默认口径 = **有效订单实付金额**:`SELECT SUM(actual_price) FROM litemall_order WHERE order_status IN (201,301,401,402,403) AND deleted=0`。用户明确说"GMV"时按行业习惯含全部下单(含未付款 101、退款前),即去掉状态过滤;用户明确说"实收/到账"再加退款扣减。时间默认按 `add_time`(下单时间)。

## 用户问"卖了多少单/订单量/单量" → COUNT(litemall_order)

订单量 = COUNT(*) on litemall_order,口径同销售额的有效订单状态过滤。"件数"是另一个概念 = SUM(order_goods.number),一单可含多件,别混淆。

## 用户问"卖了多少件/销量" → litemall_order_goods.number

销量(件)= `SELECT SUM(number) FROM litemall_order_goods`。商品维度销量榜:按 `goods_id` GROUP BY。严格口径应排除退款订单明细:JOIN litemall_order 且 order_status NOT IN (202,203)。order_goods.price×number 是商品维度销售额,注意它会大于订单侧 goods_price 之和的差 = 未退款口径差。

## 用户问"卖得最好的商品/爆款/热销榜/TOP商品" → order_goods 聚合 + goods

销量榜:`SELECT og.goods_id, g.name, SUM(og.number) AS 总销量 FROM litemall_order_goods og JOIN litemall_goods g ON g.id=og.goods_id WHERE og.deleted=0 GROUP BY og.goods_id ORDER BY 总销量 DESC LIMIT 10`。销售额榜把 SUM(number) 换成 SUM(number*price)。当前库的绝对爆款是"母亲节礼物-舒适安睡组合"(约 2.1 万件,远超第二名,居家类目)。

## 用户问"复购/回头客/老客" → 用户下单次数≥2

复购用户 = 下单≥2 次的用户。复购率 = 下单≥2次用户数 ÷ 有下单用户数(当前约 600 下单用户)。时间限定时(如"2026年Q2的复购率")在订单时间上过滤后计数。

## 用户问"新用户/新客" → user.add_time 或首单时间

"本月新用户"= `litemall_user` 注册时间(add_time)在本月的;"新客成交"= 注册时间与首单时间同月的用户数。"拉新"分析用注册量,"新客转化"用两者交集。

## 用户问"退款/退货/售后/退单" → litemall_order(202/203) + litemall_aftersale

退款申请中 = `order_status=202`;已完成退款 = `203`。售后明细(原因、类型、处理时间)在 `litemall_aftersale`:type 0=未收货仅退款,1=已收货退款,2=退货退款;status 1=处理中,3=退款成功。金额用 `refund_amount`(可能部分退款)。退款率 = 退款订单 ÷ 有效订单。

## 用户问"优惠券/满减/券" → litemall_coupon + litemall_coupon_user

券规则(满99减5/10/15、新用户券)在 `litemall_coupon`;用户领券、核销在 `litemall_coupon_user`(status:0未用 1已用 2过期)。订单实际抵扣金额看订单表 `coupon_price`。用券的订单 = `coupon_price > 0`。

## 用户问"评价/评论/好评/差评/满意度" → litemall_comment(⚠演示数据有坑)

评论在 `litemall_comment`(type=0 商品评论,value_id=goods_id)。**注意两个坑**:① star 字段绝大多数为 1(官方演示数据特征),"好评率"无业务意义;② 评论时间在 2018-2020,与订单时间 2025-2026 不重叠,不能按同期分析。可答:各商品评论量、带图率(has_picture)、评论关键词、商家回复率(admin_content 非空)。

## 用户问"库存/缺货/补货" → litemall_goods_product.number

库存 = `litemall_goods_product.number`(SKU 级)。低库存 = 数量低于阈值(如 10)的在售货品。商品表本身无库存字段。

## 用户问"快递/物流/发货/配送" → litemall_order.ship_*

快递公司分布 = `ship_channel` GROUP BY(顺丰/中通/圆通/韵达/京东);发货时效 = `ship_time − pay_time`(平均约 27 小时);"未发货订单" = `order_status=201`(已付款未发货)。

## 用户问"地域/地区/哪里的人买得多" → litemall_order.address 前缀

地址是文本快照("广东省深圳市南山区xx路x号"),无地区码表。省份分布:`SUBSTRING_INDEX(address,'省',1)`,直辖市(北京/上海/天津/重庆)需单独处理;城市:`SUBSTRING_INDEX(SUBSTRING_INDEX(address,'市',1),'省',-1)`。

## 用户问"活跃用户" → last_login_time 或近期下单

登录活跃 = `litemall_user.last_login_time` 近 N 天;下单活跃 = 近 N 天有有效订单的用户数。库里没有浏览行为,无法算"日活(DAU)"的完整口径,只能给登录/下单口径并说明。

## 用户问"客单价/人均消费" → 销售额÷订单数

客单价(AOV)= 有效订单销售额 ÷ 有效订单数(当前约 1,249 元);"人均消费/ARPU"= 销售额 ÷ 去重下单用户数。两个口径不同,按用户用词选择并标注。

## 用户问"哪些商品快过期/临期/滞销" → 滞销可答,过期无数据

滞销(动销差)= 在售但统计期内无销量的商品(goods LEFT JOIN order_goods 求无记录者);"临期/保质期"库中无字段,无法回答。
