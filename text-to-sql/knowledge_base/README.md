# litemall 业务知识库(text-to-SQL 向量检索专用)

本目录是 `litemall` 业务数据库(本地 MySQL,库名 `litemall`)配套的**电商业务领域知识库**,供 text-to-SQL Agent 在生成 SQL 前做向量检索(RAG)。解决的核心问题:**用户用口语提问时,agent 如何知道该查什么、按什么口径算、哪些问题答不了**。嵌入模型:BGE-M3(1024 维)+ bge-reranker-v2-m3 重排。

表结构/字段注释**不在本库维护**——运行时直接从 `information_schema` 抽取,两者在 prompt 中互补(本库给业务语义,schema 给物理结构)。

## 数据库速览(详细 schema 运行时从 information_schema 读取)

核心业务链:**用户 → 商品 → 订单 → 营销 → 售后/评价**,共 11 张表:

`litemall_user`(601 用户)、`litemall_goods`(239 商品)、`litemall_goods_product`(244 SKU/库存)、`litemall_category`(93 两级类目)、`litemall_brand`(49 品牌)、`litemall_order`(5 万订单)、`litemall_order_goods`(8 万明细,成交快照)、`litemall_coupon`(4 券种)、`litemall_coupon_user`(1.2 万领券)、`litemall_aftersale`(4,340 售后)、`litemall_comment`(1,004 评论,演示数据)。

订单时间范围 2025-04-01 ~ 2026-10-12;金额单位元;有逻辑删除字段 `deleted`。

## 全局检索约定(建议同时写进 system prompt)

1. 统计一律加 `deleted = 0`;金额单位元。
2. 有效订单 = `order_status IN (201,301,401,402,403)`;订单时间默认 `add_time`。
3. 利润/转化率/临期等问题先查《00_业务背景与数据边界》,命中"数据边界"类知识时**明确声明答不了并给替代口径**。
4. 订单维度金额用 `litemall_order` 单表;商品维度销量/销售额用 `litemall_order_goods`,禁止 join 后对订单金额重复求和。

## 向量化切块建议

- **按 `##` 标题切块**,每个二级标题下是一个完整知识点(自包含,不含跨块引用);表名、字段名、状态码都在块内明示。
- **块前缀必须拼**:`【文档主题】+ 块标题`,如 `【业务概念映射】用户问"卖得最好的商品/爆款" → order_goods 聚合 + goods`,可显著提升 BGE-M3 召回命中率。
- 高价值独立块:01 文档的每个映射条目、02 文档的每个指标、07 文档的每个问句(问题原文与 SQL 同块)。
- 建议 top_k=20 向量召回 → reranker 重排 → top 5 入 prompt;另将 README 的"全局检索约定"整段作为常驻 prompt,不走向量。
